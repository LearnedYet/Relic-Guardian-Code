## Easy-to-Miss Points

- In this project's Unity 6.3 Input Actions Editor, select the `Jump` action and verify `Action Type = Button`; the interface does not show the separate `Control Type` field mentioned by some older tutorials.
- Unity API method names must be exact: `GetComponent`, not `_GetComponent`.
- C# operators and punctuation must use English half-width characters. The inequality operator is `!=`, not the full-width `！` and not JavaScript's `!==`.
- Constructor argument lists cannot have an extra trailing comma before `)` in the C# version used here; for example use `new Vector3(input.x, 0f, input.y)`.
- C# multiplication uses a single `*`, not `**`.
- Unity API names are case-sensitive and must be spelled exactly: `Time.deltaTime`, not `time.daltatime`.
- `=` assigns a value, while `==` compares values. A `bool` property such as `isGrounded` can be used directly in an `if` condition without writing `= true` or `== true`.
- A component reference such as `inputReader` is needed before reading `inputReader.MoveInput`.
- The input's vertical value is named `y`, but it becomes the world's forward/back axis `z`.
- A field and a temporary local variable cannot share the same name in `ConsumeJump()`; use names such as `jumpRequested` and `wasJumpRequested` to distinguish the stored request from its saved old value.
- An unassigned enum field uses the member whose underlying numeric value is `0`; in `PlayerActionState`, that member is `Free`.
- Do not store `CanMove` or `CanJump` as manually synchronized fields when they can be derived reliably from the authoritative current action.
- `&&` evaluates from left to right and stops as soon as one condition is false. This is why an absent or rejected request prevents the later attack-animation call.
- C# keywords are case-sensitive: use lowercase `null`. Choosing an unrelated uppercase `Null` autocomplete item can add an unnecessary namespace import.
- `[SerializeField]` makes a private field serialized and Inspector-visible; it does not turn that field into a C# property or create an independent data asset.
- Each `EnemyHealth` component instance stores its own `currentHealth`. `PlayerCombat` requests damage through `TakeDamage()` rather than taking ownership of that private field.
- A weapon model should be a child of a reusable right-hand socket. Change the weapon child's local transform for model-specific alignment; do not repeatedly rewrite the character bone or constraint setup.

## Mastery Check Rule

A topic moves from **Practising** to **Understood** only after more than one suitable check. Depending on the topic, checks may include explaining it in their own words, identifying existing code behaviour, completing or correcting a short fragment, predicting an outcome, and verifying it in Unity. Seeing an explanation or replying "okay" is not sufficient evidence by itself.

## Learning Rhythm

Each small topic follows: short recall, small explanation, small practice, Unity verification when applicable, spaced review, and an observable-progress record. Limit one check to one or two concepts. The goal is practical use and explanation, not reciting definitions.
